# 后台端到端测试清单（加载防卡死 + 提交链路加固）

更新时间：2026-03-26  
适用范围：`/admin` 后台核心页面

---

## 1. 测试目标

- 验证后台页面在接口异常/超时场景下不会无限 Loading。
- 验证页面具备统一错误提示与“查询/重试”能力。
- 验证关键提交动作（保存/删除/提交）具备超时控制、失败提示与成功反馈。

---

## 2. 测试前准备

- 启动项目并可访问后台：`/admin`
- 准备一个可登录管理员账号
- 建议浏览器打开控制台（Console + Network）
- 建议准备两类环境：
  - 正常网络
  - 弱网或模拟接口失败（可通过 DevTools Network 限速或临时断网模拟）

---

## 4. 通用加载测试（每个页面都执行）

### 步骤

1. 打开目标页面（首次进入）。
2. 刷新页面（Cmd/Ctrl + R）重复进入 2~3 次。
3. 人为制造异常（断网 10~15 秒或限速）后刷新页面。
4. 观察是否出现错误提示条。
5. 点击错误提示中的“查询/重试”按钮。

### 预期结果

- 页面不会一直停留在 `Loading...`。
- 异常时出现可见错误提示（而不是静默失败）。
- 点击“查询/重试”后可重新发起请求。
- 网络恢复后可成功加载数据。

---

## 5. 关键提交动作测试

## 5.1 Dashboard（`/admin`）品牌保存

### 步骤

1. 修改品牌名（Brand Name）。
2. 点击保存。
3. 刷新页面确认值是否保留。
4. 断网后再次点击保存。

### 预期

- 成功时显示保存成功提示。
- 失败时显示明确错误提示，不会无响应。
- 恢复网络后可再次保存成功。

---

## 5.2 站点设置（`/admin/site`）保存

### 步骤

1. 修改 `Brand Name / SEO / 首页开关 / 法务链接` 任意 1~2 项。
2. 点击保存。
3. 刷新后确认配置持久化。
4. 弱网或断网状态下重复保存。

### 预期

- 成功时有 success toast。
- 失败时有 error toast（包含可理解错误）。
- 不会出现“点击保存后无限等待”。

---

## 5.3 安全设置（`/admin/security`）改密码

### 步骤

1. 输入旧密码、新密码、确认密码。
2. 点击提交。
3. 模拟弱网/断网再次提交。

### 预期

- 正常返回时成功提示并清空输入框。
- 异常时显示错误文案。
- 请求超时后可恢复再次提交。

---

## 5.4 剧目详情（`/admin/series/detail`）

### 步骤

1. 触发“删除剧目”（建议使用测试数据）。
2. 触发“批量 HLS 转码”。
3. 触发“热门 HLS 转码”。

### 预期

- 每个动作都有成功/失败反馈。
- 失败时不会静默，可看到错误提示。
- 成功后列表状态会刷新。

---

## 5.5 剧集管理（`/admin/series/episodes`）

### 步骤

1. 删除单集（测试数据）。
2. 对单条剧集执行资源健康检查。
3. 执行可见列表批量健康检查。

### 预期

- 删除、检查均有明确反馈。
- 异常时提示失败原因，不会卡住。
- 成功后数据/状态可见变化。

---

## 5.6 标签管理（`/admin/series/tags`）

### 步骤

1. 删除某条剧目的某个标签。
2. 在异常网络下重复操作。

### 预期

- 成功时提示“已删除”并刷新。
- 失败时有错误提示，页面可继续操作。

---

## 5.7 上传页（`/admin/series/upload`）

### 步骤

1. 输入已存在标题，触发“标题查重”。
2. 上传封面（png/jpg/webp）。
3. 上传视频文件并执行提交流程（建议小文件做冒烟）。
4. 弱网下重复测试查重/封面上传/预签名上传。

### 预期

- 标题重复会被拦截并提示。
- 封面上传失败有错误提示，成功后能回填 URL。
- 视频预签名异常会进入重试/失败提示，而不是卡死。

---

## 6. 数据页加载测试

页面：`users / recharge / views / history / favorites / likes / access-list / config`

### 步骤

1. 打开页面，确认加载成功。
2. 刷新页面，观察是否出现闪断卡死。
3. 弱网/断网刷新，检查错误提示。
4. 点击“查询/重试”恢复。

### 预期

- 无无限 loading。
- 错误时可重试恢复。

---

## 7. 回归重点（和本次改造直接相关）

- 所有关键页面都应具备：
  - 超时控制（避免挂死）
  - 错误提示（用户可见）
  - 重试入口（恢复能力）
- 所有关键提交动作都应具备：
  - 响应成功校验（`res.ok + json.ok`）
  - 失败 toast（含错误映射）
  - 成功 toast（可确认动作生效）

## 9. 验收标准（通过条件）

- 覆盖页面均通过“正常网络 + 异常网络”两轮测试。
- 无页面出现“无限 Loading 且无错误提示”。
- 无关键提交动作出现“点击后无反馈”。
- 失败可重试，恢复网络后可成功完成操作。
